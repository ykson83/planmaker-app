# 설계 결정 기록

## 2026-09-26 — 프로젝트 기준

- 개발 저장소는 `planmaker-app`이다.
- 백엔드는 Python/FastAPI로 개발한다.
- 현재 정적 화면은 FastAPI가 제공한다.

## 2026-09-26 — 초기 도메인

- `User`, `OAuthIdentity`, `Plan`, `PlanParticipant`, `Notification`으로 시작한다.
- Availability, 예약, AI 코스 추천, 실제 푸시 알림은 초기 구현 범위에 넣지 않는다.

## 2026-09-26 — 로그인

- 초기 활성 로그인 제공자는 카카오, 네이버, Google이다. Apple은 제공자 enum과 향후 확장 대상에는 유지하되, Apple Developer 설정이 준비될 때까지 로그인 화면과 OAuth route에서 비활성화한다.
- 첫 OAuth 로그인 시 Bakii 닉네임 입력을 필수로 한다.
- 닉네임은 서비스 내에서 고유하다.
- OAuth 계정은 `OAuthIdentity`로 분리하고 공급자 고유 사용자 ID로 식별한다.
- 이메일·비밀번호 로그인은 초기 범위에 넣지 않는다.
- OAuth 완료 뒤에는 불투명한 서버 세션 ID를 `HttpOnly` 쿠키로 유지한다. 세션은 서버에서 검증·폐기하고, 최근 활동 기준 14일 후 만료한다. 로그아웃은 해당 세션을 즉시 폐기한다. 운영 환경 쿠키에는 `Secure`, `HttpOnly`, `SameSite=Lax`를 적용한다. 안전하지 않은 HTTP 로컬 개발 환경에서만 `Secure`를 끈다.
- 쿠키 인증으로 상태를 바꾸는 요청에는 서버 세션에 연결된 CSRF 토큰을 `X-CSRF-Token` header로 제출하게 한다. OAuth 공급자 토큰은 서버 외부로 전달하지 않는다.

## 2026-09-26 — 개발 DB 환경

- 개발 MySQL은 Docker Compose의 MySQL 8.4 LTS 이미지로 실행한다. 데이터베이스 문자셋·collation은 `utf8mb4`·`utf8mb4_0900_ai_ci`로 고정한다. 포트, 데이터 볼륨, 초기 계정은 Compose와 `.env.example`로 재현하고, 실제 비밀번호는 커밋하지 않는 `.env`에 둔다.
- DB 스키마 변경은 Alembic migration으로만 적용한다.

## 2026-09-26 — 닉네임 정책

- 닉네임은 NFC 정규화 뒤 한글, 영문, 숫자, 밑줄(`_`)만 사용해 2~16자로 제한한다.
- 중복 판단은 영문 대소문자를 구분하지 않는다. 닉네임은 변경할 수 있으나, 초기 버전에는 변경 횟수 제한을 두지 않는다.
- 초대용 사용자 검색은 공개 사용자 목록이 아니라 2자 이상 닉네임 접두 검색으로 제한하고, 최대 10건만 반환한다.

## 2026-09-26 — 약속 초대와 권한

- 이미 가입한 사용자는 닉네임 검색으로 초대한다. 초대된 사용자의 최초 상태는 `PENDING`이다.
- 미가입자는 약속별 초대 링크로 초대한다. 링크는 충분히 긴 무작위 토큰의 해시만 서버에 저장하고, 기본 7일 후 만료된다. 링크를 연 사용자는 OAuth 로그인과 닉네임 온보딩 뒤 참여를 명시적으로 확인해야 하며, 확인 시 `ACCEPTED` 참여자로 추가된다.
- 링크는 만료 또는 폐기 전까지 재사용할 수 있다. 생성자가 폐기할 수 있고, 취소되었거나 시작 시각이 지난 약속에는 사용할 수 없다. 이 기능 구현 시 `PlanInvitationLink` 지원 엔터티와 migration을 추가한다.
- Plan 생성자는 생성과 동시에 `ACCEPTED` 참여자로 추가된다. 생성자만 약속의 수정, 취소, 사용자 초대, 초대 링크 생성·폐기를 할 수 있다.
- 참여자는 자신의 응답만 `PENDING`, `ACCEPTED`, `DECLINED` 사이에서 바꿀 수 있다. `DECLINED` 후에도 약속이 예정 상태이면 다시 수락할 수 있다.
- 취소는 `status=CANCELED`로 기록을 보존한다. 취소된 약속은 조회만 가능하며 수정, 초대, 링크 사용, 참여 응답 변경, 재활성화를 허용하지 않는다.
- 초기 버전에는 참여자 강제 퇴장 및 공동 편집 기능을 제공하지 않는다.

## 2026-09-26 — 시간과 알림

- 날짜·시간은 UTC로 저장하고 `Asia/Seoul` 기준으로 표시한다.
- 초기 알림은 인앱 알림 목록이다.
- Android/iOS 푸시 알림은 기본 약속 흐름 이후에 추가한다.
- API는 timezone-aware ISO 8601 시각만 받고 UTC로 정규화해 반환한다. 웹 화면의 입력과 표시는 `Asia/Seoul`로 변환한다.
- 초대 시 초대받은 사용자에게, 참여 응답 변경 및 초대 링크 참여 시 생성자에게, 약속 수정·취소 시 변경한 사람을 제외한 참여자에게 알림을 만든다. 초기에는 알림 하나씩만 읽음 처리한다.

## 2026-09-26 — 계정 범위

- 하나의 User에 여러 OAuthIdentity를 연결할 수 있는 데이터 구조는 유지한다. 다만 초기 UI와 API에는 계정 연결·병합 기능을 넣지 않는다.
- 계정 탈퇴는 약속 이력, 개인정보 처리, 재가입 정책을 함께 설계해야 하므로 초기 기본 약속 흐름에서는 제외한다. 공개 서비스 전 별도 결정과 구현 대상으로 둔다.
